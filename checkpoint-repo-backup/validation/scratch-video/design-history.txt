# 🧠 Model layer

Don't tie the entire system to one model.

Create a model abstraction:

```text
                    MODEL ROUTER
                         │
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
       GPT             Claude           Gemini
        │                │                │
        └────────────────┼────────────────┘
                         ▼
                    Local Models
```

Then the agent can choose:

```text
Simple task → cheap/fast model

Coding → strongest coding model

Huge document → long-context model

Image understanding → vision model

Local/private task → local model
```

This would make your software **model-agnostic**.

# 🛡️ One thing I would NOT do

Don't give version 1 unrestricted control over:

* your entire filesystem
* administrator/root access
* passwords
* financial accounts
* arbitrary downloads
* unrestricted network activity
* permanent self-modification

Instead use:

```text
                    PERMISSION ENGINE
                           │
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
       SAFE             APPROVAL          BLOCKED
       actions          required          actions
```

For example:

```text
Read project files       → ALLOW
Create source file       → ALLOW
Run tests                → ALLOW
Install npm package      → ASK
Delete directory         → ASK
Run administrator cmd    → ASK
Send email               → ASK
Financial transaction    → BLOCK/explicit workflow
```

That gives you a powerful agent **without turning it into a liability**.

# PERSONAL AI OPERATING SYSTEM — MASTER CONSTRUCTION PROMPT

## 1. PROJECT VISION

We are building a private, personal, persistent AI system inspired by the capabilities of modern coding agents, computer-use agents, autonomous workers, and Jarvis-style assistants.

This is **not simply a chatbot**.

The long-term goal is to create a personal AI operating layer that can:

* Understand goals
* Reason and plan
* Use tools
* Control computers and applications
* Learn from documents, courses, websites and other resources
* Learn specialized workflows directly from its user
* Remember information and experiences
* Build and maintain software
* Work autonomously
* Run long-running missions
* Collaborate through specialized AI agents
* Verify its own work
* Recover from failures
* Improve its capabilities in a controlled way
* Communicate through text and voice
* Operate across Windows, Android, remote computers and cloud machines
* Preserve its identity, knowledge, skills, memories and experiences when moved to another computer

The system should ultimately feel like a **persistent digital worker and companion**, rather than a collection of disconnected AI features.

> **The AI must not be permanently tied to a particular AI model, computer, application or operating system.**

Changing the underlying model should not erase the AI's accumulated state.

Moving to a new computer should allow the same AI to continue with its accumulated knowledge and experience.

# 43. SOURCE CODE STRATEGY

An existing source archive may be available as a possible foundation.

Before deciding whether to reuse it:

1. Inspect the entire source tree.
2. Identify its architecture.
3. Identify its existing capabilities.
4. Identify dependencies.
5. Identify security risks.
6. Identify outdated components.
7. Map existing components to this specification.
8. Identify missing components.
9. Determine what can be reused.
10. Determine what should be rewritten.
11. Determine what should be discarded.

Do not assume that existing code should become the final architecture.

Treat it as a potential starting point.

# 44. IMPLEMENTATION RULES

The eventual implementation must prioritize:

### Reliability

Prefer deterministic, testable mechanisms over fragile automation where possible.

### Security

Least privilege by default.

### Transparency

The user should understand what the AI is doing.

### Recoverability

Important operations should be reversible where possible.

### Modularity

Components should be replaceable.

### Model independence

AI state must not depend on one model provider.

### Portability

The AI should be capable of migrating between machines.

### Extensibility

New tools, models, agents and skills should be addable without rebuilding the entire system.

### User control

Autonomy should always operate within explicit policies and permissions.
