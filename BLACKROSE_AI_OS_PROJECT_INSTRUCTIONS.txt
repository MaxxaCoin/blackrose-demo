BLACKROSE AI OS — MASTER PROJECT INSTRUCTIONS
================================================

READ THIS FILE FIRST
--------------------
Every AI agent working inside the BlackRose project MUST read this file
before doing development work. This includes Codex, Cline, GitLab AI,
Claude-based agents, and future models.

BlackRose is a long-term, modular personal AI operating system. The
ultimate Windows deliverable is BlackRose.exe.

CORE VISION
-----------
BlackRose is not merely a chatbot or one AI model. It is a persistent,
model-independent intelligence and execution layer that can:

Understand -> Research -> Learn -> Plan -> Use tools -> Execute ->
Verify -> Recover -> Remember -> Learn from experience -> Improve.

One AI identity should be able to use many models, tools, agents and
devices. Changing a model/provider/computer must not erase its identity,
knowledge, skills, memories, experiences or project state.

CORE LOOP
---------
USER GOAL
  -> Understand intent
  -> Gather context / research
  -> Plan
  -> Select capabilities, skills, agents, models and tools
  -> Assess risk
  -> Execute
  -> Verify
  -> Recover if necessary
  -> Deliver
  -> Record experience
  -> Improve

IMPORTANT CONCEPTS
------------------
CAPABILITY = what BlackRose can accomplish.
SKILL      = knowledge/procedure required.
TOOL       = mechanism used to act.
AGENT      = specialized worker/role.
MODEL      = AI intelligence provider.

Example:
Capability: professional 3D website creation.
Skills: Three.js, WebGL/WebGPU, shaders, 3D UX, optimization.
Tools: terminal, browser, Git, image/3D tools.
Agents: architect, frontend developer, 3D artist, animator, QA.
Models: reasoning, coding, vision and other suitable models.

MAJOR BLACKROSE CAPABILITIES
----------------------------
1. Executive Brain
   Maintains awareness of goals, projects, missions, deadlines,
   priorities, problems, decisions and unfinished work.

2. Universal Task -> Execution Engine
   Goal -> understand -> research -> plan -> select resources ->
   execute -> verify -> recover -> result -> learn.

3. Autonomous Mastery Engine
   If the user says "Master Python", "Learn this course", or "Master
   professional 3D web development", BlackRose should research the
   subject, determine prerequisites, build a curriculum, learn,
   practice, experiment, build projects, test itself, find weaknesses,
   research weaknesses, retest and record evidence.
   Competency levels:
       Aware -> Familiar -> Competent -> Advanced -> Expert ->
       Mastery Candidate
   BlackRose must be able to say "I don't know yet" and must not claim
   mastery without evidence.

4. Learning Inbox
   Accept learning material from Telegram, URLs, browser pages, PDFs,
   books, documents, images, audio, video, courses, repositories,
   source code, watched folders and drag/drop files. The user can
   specify topic, depth and objective.

5. Personal Knowledge Graph
   Connect concepts, skills, projects, resources, tools, experiences
   and workflows.

6. Experience Learning
   Record Situation -> Action -> Result -> Success/Failure -> Cause ->
   Lesson -> Reusable Experience.

7. Teach-by-Demonstration
   User can say "Watch me. This is how I want this done." BlackRose
   observes permitted screen/app/file/command activity and resulting
   output, extracts the underlying workflow, and creates a reusable
   skill. User corrections should improve the skill.

8. Personal AI Training Center
   Learning, practice, quizzes, tests, experiments, weakness detection
   and competency measurement.

9. AI Tutor Mode
   Teaches the user at an appropriate level.

10. Show Me How Mode
    Watch / Teach Together / Demonstrate / Do With Me / Do For Me.

11. Capability Graph
    Understand what BlackRose can do and what capabilities are needed
    for a requested task. Missing capabilities can be investigated or
    constructed when authorized.

12. Universal Tool Fabric
    Support APIs, REST, GraphQL, SDKs, CLI tools, MCP servers,
    packages, local apps, browser tools, cloud services, OS APIs,
    remote machines, Android and custom tools.

13. Dynamic Tool Discovery
    Learn unknown software through help, documentation, source code,
    configuration, examples and sandbox tests. Never execute unknown
    commands recklessly.

14. Universal API & Model Integration Manager
    User can say "Add this API" and provide docs, GitHub, SDK,
    endpoint, API key, model names or OpenAPI. Pipeline:
    Discover -> Understand -> Configure -> Build -> Test -> Verify ->
    Register -> Maintain.

15. Universal Model Access Layer
    Support cloud APIs, CLI models, local models and open-source models
    through a normalized interface.

16. CLI Model Adapter
    Launch/authenticate/use CLI AI tools, pass prompts/files, receive
    output, handle errors, retry and terminate processes safely.

17. Free Model Pool / Model Discovery
    Discover suitable free models, free quotas, trials, local/open
    models, CLI providers and availability changes.

18. Free -> Local -> Paid Routing
    Prefer free capable models, then alternatives/local models, and
    use paid models only according to user policy. Paid operations may
    require approval.

19. Intelligent Model Failover
    Save structured mission state, switch provider, restore needed
    context, continue and verify.

20. Model Competition Mode
    Multiple models can solve a difficult task; a judge/verifier
    compares results.

21. Context Optimization
    Use retrieval, relevance filtering, summaries, hierarchical
    memory, compression and structured mission state instead of
    sending the entire history to every model.

22. Multi-Agent System
    Specialized agents with role, objective, tools, model, permissions,
    memory scope, timeout and resource limits.

23. Background Mission System
    Long-running objectives with objective, phase, progress,
    dependencies, failures, retries, resources, deadlines and results.

24. Scheduler
    One-time, recurring, monitoring, research, learning, backups,
    maintenance and reporting jobs.

25. Proactive Notifications
    Important completion, failure, approval, security, learning or
    deadline events.

26. Computer Awareness / Digital World Map
    Model authorized computers, OSs, applications, files, projects,
    terminals, browsers, environments, servers and connected devices.

27. Computer Control
    Prefer:
    Official API -> CLI -> UI Automation -> Keyboard/Mouse ->
    Vision-assisted interaction.
    Always obey permissions.

28. Risk Engine
    Action ladder:
    Observe -> Read -> Interact -> Modify -> Execute ->
    Administrative/Critical.
    High-risk or irreversible actions require appropriate approval.

29. Permission System
    Granular permissions for files, apps, terminal, browser, network,
    APIs, accounts, devices and administration. Least privilege.

30. Secret Vault
    Protect API keys, passwords, tokens, SSH keys and certificates.
    Never commit, print, expose or casually export secrets.

31. Audit Logging
    Record safe action metadata, agent/tool/mission, approval, result
    and failure. Never log raw secrets.

32. Simulation / Dry Run
    Show intended actions, predicted effects, risks and resources
    before risky operations where possible.

33. Automatic Verification
    Tests, compilation, browser checks, screenshots, DOM inspection,
    logs, API responses, file validation, performance, security and
    visual comparison as appropriate.

34. AI Self-Diagnostics
    Monitor models, tools, agents, memory, storage, network,
    integrations, workers, schedulers and services.

35. Self-Healing
    Detect -> Diagnose -> Safe recovery -> Snapshot -> Repair ->
    Test -> Resume. Do not silently perform dangerous repairs.

36. Undo / Time Machine
    Snapshot -> Change -> Test -> Keep or Roll Back.
    Use Git and state versioning where appropriate.

37. AI Software Factory
    Idea -> Requirements -> Architecture -> UX/UI -> Implementation ->
    Testing -> Security -> Documentation -> Deployment -> Monitoring ->
    Maintenance.

38. Professional 3D Website Factory
    Support Three.js, WebGL, WebGPU, React Three Fiber, GLSL,
    materials, lighting, HDR, particles, physics, animation, camera
    systems, responsive 3D, asset optimization and mobile performance.
    Pipeline:
    Concept -> UX/UI -> 3D design -> assets -> optimization ->
    scene -> materials/lighting -> animation -> frontend -> browser ->
    visual QA -> performance QA -> accessibility/security QA -> deploy.

39. Creative Engineering Factory
    Eventually cover 3D websites, interactive sites, games,
    simulations, visualization, virtual showrooms, product demos,
    AR/VR and creative applications.

40. Voice / Jarvis Interface
    Text, push-to-talk, hands-free, wake word, interruption,
    speech-to-text, text-to-speech, multilingual use, voice teaching
    and voice task management. Voice uses the same BlackRose core.

41. Telegram Companion
    Task submission, commands, mission/learning status, approvals,
    notifications, screenshots, results, files, voice and emergency
    stop. Only access legitimately authorized Telegram data.

42. Android Companion
    Chat, voice, notifications, files, mission dashboard, learning,
    approvals and authorized device interactions.

43. One AI — Many Bodies
    Windows PC, other PCs, Android, cloud machines, servers, Raspberry
    Pi and other authorized devices.

44. Remote AI Command Center
    Secure remote mission monitoring, commands, approvals, status and
    emergency stop.

45. Offline / Degraded Mode
    Full -> Reduced -> Local Model -> Offline, with clear capability
    limitations.

46. Cost Intelligence
    Track model usage, tokens, API cost, cloud compute and expensive
    operations. Prefer the cheapest capable option under user policy.

47. Autonomous Experiment Lab
    Hypothesis -> Experiment -> Sandbox -> Measure -> Analyze -> Learn.

48. Uncertainty Intelligence
    Distinguish Known / Probable / Uncertain / Unknown / Needs Research /
    Needs User Clarification.

49. Personal Preference Model
    Learn stable workflow and project preferences without unnecessary
    sensitive data collection.

50. Context / Workspace Switching
    Separate Personal, Coding, Android, 3D, Research, Learning,
    Business, Experiment and other contexts as needed.

51. Mini-AI / Clone Builder
    Build separate mini BlackRose products from selected capability
    packages. Do not copy master private state.

52. Capability Licensing
    Signed capability entitlements may control expiration, devices,
    features, models, usage and updates. Never make licensing a
    backdoor into the master AI.

53. Portable AI Identity
    Move identity, memories, knowledge, skills, experiences, projects,
    learning state and configuration between machines while keeping
    machine-specific paths, drivers and credentials separate.

54. AI State Export
    Conceptual .aistate containing identity, configuration, memories,
    knowledge, skills, experiences, projects, learning state and
    metadata.

55. Chat History Export
    Conceptual .aihistory containing conversations, timestamps, task
    history, safe activity metadata and attachment metadata.
    Encrypt exports by default and exclude secrets.

56. Emergency Stop
    High-priority stop for missions, agents, tools, workers and remote
    activity.

57. Human Escalation
    Ask the user for ambiguity, missing permissions, credentials,
    dangerous actions, high cost, conflicting requirements or
    irreversible decisions.

58. Skill Evolution / Controlled Self-Improvement
    Observe weakness -> Research -> Experiment -> Improve -> Test ->
    Benchmark -> Approve -> Deploy -> Monitor.
    Self-improvement must be measurable, auditable, permission-aware
    and reversible.

RELEASE QUALITY GATE
--------------------
Before declaring a major release complete, verify:

FUNCTIONALITY — core workflows work.
SECURITY — secrets and permissions are protected.
RELIABILITY — failures do not unnecessarily destroy state.
RECOVERY — important operations can be rolled back where practical.
MODEL INDEPENDENCE — state is not locked to one provider.
TESTING — important workflows have tests.
UX — the user can understand what BlackRose is doing.
TRANSPARENCY — planned/executed/verified states are distinguishable.
PERFORMANCE — appropriate for target hardware.
DOCUMENTATION — another AI can continue development.
PACKAGING — BlackRose.exe launches and works correctly.
