build: interactive signer for password-protected release keys

The updater key at ~/.tauri/blackrose.key is password-protected and the
password is deliberately stored nowhere. That made every signed release depend
on the user having BLACKROSE_SIGNING_PASSWORD already exported in a shell the
agent cannot see.

sign-release.ps1 prompts for it with Read-Host -AsSecureString, converts it
in-process, and hands it to the existing build-desktop-signed.ps1. The
plaintext is never echoed, never written to disk, and never passed on a command
line (which would be visible in process listings).

Two guards, both added after the first run misreported success:

  * The status/log directory is resolved and asserted to EXIST before the
    build. It was originally computed one level too shallow, so every status
    write failed AFTER the build — and a failed Out-File still left
    $LASTEXITCODE at 0, so the script printed "signature verified" for a build
    that never ran. That is the worst possible failure mode for a release
    script, so a missing or empty log is now a hard failure regardless of the
    exit code.

Release built and signature produced for 0.9.15; payload verified by extraction.
