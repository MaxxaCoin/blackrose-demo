fix(desktop): CSP, narrower updater grant, and an update banner that never gives up

Three items flagged as deferred, closed together.

1. csp was null — the webview had no Content-Security-Policy at all, so the
   two XSS sinks that were fixed had no second layer behind them. Now:
     default-src 'self'; script-src 'self' 'unsafe-inline';
     style-src 'self' 'unsafe-inline'; img-src 'self' data:;
     media-src 'self' data: blob:; font-src 'self' data:;
     connect-src 'self' ipc: http://ipc.localhost data:;
     object-src 'none'; base-uri 'none'; frame-ancestors 'none';
     form-action 'none'
   'unsafe-inline' is retained for script-src and style-src because the shipped
   UI genuinely has inline script and ~40 inline style attributes; removing it
   would mean a build step to hash or extract them, which is a larger change
   than this. What the policy does buy is real: object-src/base-uri/
   frame-ancestors/form-action are denied outright, and nothing may be loaded
   or connected to from anywhere but this app. That is what stops a
   provider-controlled string turning into a remote fetch or a remote script.
   media-src allows data: because the approval chime is a data: URI.

2. The remote-updater capability granted allow-app-shutdown to ANY
   http://127.0.0.1:* origin. Shutting the app down is a local-only action and
   had no business in a remote grant. Moved to the local `default` capability
   so the ⏻ button keeps working while remote origins lose it. The updater
   commands stay remote because the page genuinely has to call them.

3. The update banner gave up permanently after 120 polls (~6 minutes), so an
   app left open longer than that could never show a late notice — which is
   exactly how a published release went unnoticed here. It now polls fast for
   the first 20 attempts, then settles into a once-a-minute heartbeat, and only
   stops once a notice has actually been shown. One IPC round trip a minute.

Gates: tsc exit 0 | capability JSON parses.
