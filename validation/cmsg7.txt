test(trust): cover the sidebar honesty assertion

The full-trust change left effectiveAlwaysAsk() untested, and it is what the
UI renders as "what will still ask". If it kept returning the deny-list while
trust was on, the sidebar would claim it still stops for run_command when it no
longer does — a safety indicator that overstates protection is worse than none.

The first version of this assertion FAILED and was my mistake, not a product
bug: it read /api/trust after setTrust(false), so trust was off and the server
correctly returned the full deny-list. Moved to read the endpoint while trust is
still on, which is the only moment the value means anything.
