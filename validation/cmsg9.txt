fix(ui): an ephemeral port could be handed back that fetch refuses

Item 5 from the audit - the "flaky" smoke failure. It was not flaky, and it
was not in the test: it was a real bug in startWebUi.

startWebUi({port: 0}) means "let the OS pick". On EADDRINUSE the fallback
walked `wanted + 1 .. wanted + 19`. With wanted=0 that starts at PORT 1. The
Fetch spec classifies ports 1-1023 as unsafe, so undici refuses the URL with
"bad port" - while the server is listening and healthy. The caller then reports
a connect failure against something that is actually up, which is precisely the
kind of lie this file exists to avoid. It surfaced on one test and not others
purely because only that one hit the fallback path.

Fixed: when wanted is 0, retry 0 up to 5 times and let the OS hand out a
different ephemeral port. The port-scan fallback is unchanged for an explicit
port, where 8789-8807 are all safe.

Regression test starts three ephemeral servers, fetches each, and asserts every
returned port is >= 1024. Verified ports 7314/7317/7320.

Gates: tsc clean, smoke PASS, unit 51 / 0.
