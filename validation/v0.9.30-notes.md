BlackRose 0.9.30 — runtime custom tools (P1 ecosystem) + SEA bundler fix

- Runtime custom tools are here: `tool_define` / `tool_list` / `tool_remove` let you
  add your own tools at runtime. A custom tool wraps a canned shell command
  (argv, never a shell string) under a stable name + JSON schema, persisted to
  `<dataDir>/custom-tools.json`, and takes an approval mode (`ask` default,
  fail-closed, or `auto`).
- Wired into every host: CLI, local bridge, and the web UI share one registry,
  and Telegram (running inside the same process) can call them too.
- Surfaces: CLI `/tools` annotates custom tools with their approval mode;
  Telegram gets `/custom_tools` (`/ct`) + hub button; the UI manage panel adds
  define/remove (gated on trust mode or a bound Telegram, else fail-closed).
- SEA bundler fixed: the `.exe`/bundle no longer chokes on bare Node builtins
  (`fs`/`path`/`util`) and named-vs-namespace collisions — builds clean again.
- Regression coverage confirms a persisted definition becomes a runnable tool
  and executes.

Installed 0.9.29 (and earlier) apps will offer this update automatically.
