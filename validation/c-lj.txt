build: generate the updater manifest without a BOM, and assert it

The 0.9.15 publish failed twice before this existed:

  1. The manifest was uploaded under the wrong asset name (latest-0915.json),
     so the updater's latest/download/latest.json kept serving 0.9.14 while the
     release itself looked correct. Nothing in the release view shows that.

  2. Building the JSON with ConvertTo-Json emits a UTF-8 BOM, and the updater
     reader rejects the file outright — "no update available" against a
     perfectly good release. This has bitten us before.

So this script writes raw bytes with UTF8Encoding($false) and then REFUSES to
finish unless it verifies: no BOM in the first three bytes, the version round-
trips, and the embedded signature matches the .sig on disk byte for byte. A
manifest is a trust artifact; generating it should not be the loose part.
