fix: close the last two unclaimed audit rows (export stamp, signing key)

audit-state rows 6 and 8 — the two findings no agent had picked up.

Row 8 — export stamp collision (src/state/aistate.ts:124).
The stamp named the export FILE, at second resolution. Two exports in the same
second produced the same path, so the second silently overwrote the first: a
user who exported, changed something, exported again, and kept only the newer
file lost the earlier backup with no error anywhere. Now milliseconds plus a
random suffix. Second resolution is a reasonable thing to show a human and a
useless unique key.

Row 6 — updater private key auto-loaded (scripts/build-desktop.ts:213).
build-desktop.ts read ~/.tauri/blackrose.key unconditionally, so ANY build —
a routine local `npm run build:desktop`, or a CI run — pulled the release
signing key into the child process environment. That key is the entire trust
anchor of the updater: anyone holding it can sign a bundle this app will
install. Loading it is now opt-in behind BLACKROSE_RELEASE=1, and an unsigned
build says so loudly instead of failing mysteriously later.

Verified this does NOT weaken the real release path: scripts/build-desktop-signed.ps1
sets TAURI_SIGNING_PRIVATE_KEY explicitly from the key file (line 9), which the
gate passes through untouched. That is the script 0.9.12-0.9.14 were signed with.
